# 招聘源适配验收 SOP

适用于新建、修复、更新任何企业招聘适配器。接口返回、离线测试通过、真实网页可用是三个不同结论，不得相互替代。

## 真实数据底线

- 正式结果只能来自目标官网的真实响应。禁止请求失败后返回 mock、示例或硬编码岗位；fixture 只放测试路径，生产模块不得导入。
- 空列表、请求失败、登录/验证码、响应结构变化必须区分。无法确认就报告原因，不用空结果假装成功。
- 记录校招/社招/实习入口、来源地址、读取时间、字段映射及分页上限；长岗位编号保留字符串，不经过 Number。
- 详情 URL 必须来自官网返回值或实际点击观察到的路由；禁止猜路径、参数名和大小写。

## 两阶段验收

### A. 开发与审核（默认停用）

1. 只处理指定企业，使用 Ego Lite 观察官网和公开请求。限制一页列表、最多三个详情，不全量扫描。
2. 对最多三个真实岗位核对：列表名称和编号 → 实际点击地址 → 详情名称、描述。少于三个如实记录数量；样本不足、无可读详情或未获在线验证授权，状态为“待在线验收”，不得宣称接入成功。
3. 离线 fixture 单独验证字段、长编号、空数据、异常响应和分页；不能用 fixture 通过证明岗位真实。
4. 详情显示下线/关闭/404 为失效；登录、验证码、超时、空壳为待确认。HTTP 200 或列表存在不等于可投递。未逐条检查的结果必须说明未核实。
5. 将证据写入插件目录 `ACCEPTANCE.md`：入口及招聘类型、核验时间、实际列表请求、样本名称/字符串编号/详情 URL/核验结果、离线测试命令和结果、分页限制、未完成事项。仅保留最小公开证据，不存凭证、个人信息或完整响应。
6. 新插件保持停用且不绑定；交给用户审核。遇登录、短信、验证码交给用户，不绕过、不投递。

### B. 用户授权启用后

1. 审核最终文件与权限，再通过 `node plugins.mjs enable <id> --confirm` 启用并绑定目标企业。
2. 已启用插件修改后，审核变更，再用 `node plugins.mjs trust <id>` 更新指纹。不得绕过完整性检查或因报错而盲目信任。
3. 确认扫描器实际加载插件，不只检查配置中的 enabled。
4. 从产品页面仅选该企业运行一次有上限的零 Token 扫描，核对真实返回与详情；不调用 AI 评估、不提交申请。
5. 记录启用、绑定、加载、页面扫描、详情核对各自结果。失败保持“未验收”，旧链接修复不得删除用户投递记录。

## 完成声明

分别报告“离线测试”“真实详情抽查”“启用及页面验收”。不能用满分/成功图标掩盖未做的阶段；抽样通过不代表全部岗位有效。没有真实证据就不能宣布真实接入成功。
