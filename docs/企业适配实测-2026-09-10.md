只选择快手与小红书，关键词“算法、数据、工程师、产品”，30 天，不加地区限制。临时限制每家一页，点击「重新扫描（免费）」后显示 **86 个匹配：快手 77、小红书 9**。测试后恢复原每家最多三页设置。

从页面结果打开并核对：

这仅证明本次样本与扫描有效，不代表全部职位均有效。岗位和招聘项目随时间变化。

## 实测发现并修正

1. 小红书实际同域 API 是 `job.xiaohongshu.com/websiterecruit/position/pageQueryPosition`，不是旧版的 recruit 子域；真实请求参数 `recruitType=campus`、`jobProjects=[campus_autumn_27]`。地址和参数由正常页面 Network 观察，不猜测或绕过签名。实际字段为 `workplace`、`duty`、`qualification`。
2. 快手和京东旧解析器将网络失败吞成空数组；候选版明确报错并拒绝异常结构、不安全数字编号。
3. 扫描去重丢弃 hash，导致快手 100 条只保留一条。核心和 Web 的 URL 比较键现在保留这两家明确路由中的岗位编号，不改变公开链接。
4. 验收固定两秒等待可能早于正文加载；新增按预期名称有上限等待。第三方扩展探测仍被阻止，但不再使真实岗位整体变成未知。无标准投递按钮的页面仍必须通过名称、正文和真实列表验证；登录、验证码、失效、跳转和超时不放行。

新插件与详细安装证据保存在本地 `plugins.local/` 和 `.career-ops-web/enterprise-adapters/`，不包含完整生产响应或凭证，不随代码推送。失败时只重新验收有明确修正依据的候选，不自动重跑付费 Agent。
