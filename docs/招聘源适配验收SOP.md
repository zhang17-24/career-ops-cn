# 招聘源适配验收 SOP

适用于新建、修复、更新任何企业招聘适配器。接口返回、离线测试通过、真实网页可用是三个不同结论，不得相互替代。

## 真实数据底线

- 正式结果只能来自目标官网的真实响应。禁止请求失败后返回 mock、示例或硬编码岗位；fixture 只放测试路径，生产模块不得导入。
- 空列表、请求失败、登录/验证码、响应结构变化必须区分。无法确认就报告原因，不用空结果假装成功。
- 记录校招/社招/实习入口、来源地址、读取时间、字段映射及分页上限；长岗位编号保留字符串，不经过 Number。
- 详情 URL 必须来自官网返回值或实际点击观察到的路由；禁止猜路径、参数名和大小写。

## 两阶段验收

### 企业托管模式（页面「Agent 适配／重新适配」）

用户已授权验收成功后自动安装和绑定，无须重复手动启用。平台先创建独立候选目录，Agent 只修改该目录，禁止覆盖旧版、修改绑定或自行更新信任。Agent 结束后，由服务端读取真实列表并核验三个详情、静态检查和离线测试；检查失败保留旧版绑定，通过才自动启用并切换本企业。官网同域或用户已在本企业页面审核的精确域名、无额外密钥权限的候选可进入验收；未审核域名不自动放行。浏览器型适配器通过下述 browserListing 声明接入，仍须独立验收，不以 Agent 自述替代。

企业卡片「适配器设置」提供删除和回收区恢复。删除会停用、解绑并移入本地回收区，保留企业、岗位和投递记录；恢复只恢复文件，不直接信任或启用旧代码。重新适配始终创建新目录，成功切换后保留旧文件。平台配置更新失败时回滚配置，并保留本地备份。

下面的手动审核步骤仍适用于 CLI 或其他非托管模式；不能以 Agent 的分数或自述替代平台验收。

### A. 开发与审核（默认停用）

1. 只处理指定企业，使用 Ego Lite 观察官网和公开请求。限制一页列表、最多三个详情，不全量扫描。
2. 对最多三个真实岗位核对：列表名称和编号 → 实际点击地址 → 详情名称、描述。少于三个如实记录数量；样本不足、无可读详情或未获在线验证授权，状态为“待在线验收”，不得宣称接入成功。
3. 离线 fixture 单独验证字段、长编号、空数据、异常响应和分页；不能用 fixture 通过证明岗位真实。
4. 详情显示下线/关闭/404 为失效；登录、验证码、超时、空壳为待确认。HTTP 200 或列表存在不等于可投递。未逐条检查的结果必须说明未核实。
5. 将证据写入插件目录 `ACCEPTANCE.md`：入口及招聘类型、核验时间、实际列表请求、样本名称/字符串编号/详情 URL/核验结果、离线测试命令和结果、分页限制、未完成事项。仅保留最小公开证据，不存凭证、个人信息或完整响应。
6. 新插件保持停用且不绑定；交给用户审核。遇登录、短信、验证码交给用户，不绕过、不投递。

### B. 用户授权启用后

1. 审核最终文件与权限，再通过 `node plugins.mjs enable <id> --confirm` 启用并绑定目标企业。
2. 已启用插件修改后，审核变更，再用 `node plugins.mjs trust <id>` 更新指纹。不得绕过完整性检查或因报错而盲目信任。
3. 确认扫描器实际加载插件，不只检查配置中的 enabled。
4. 从产品页面仅选该企业运行一次有上限的零 Token 扫描，核对真实返回与详情；不调用 AI 评估、不提交申请。
5. 记录启用、绑定、加载、页面扫描、详情核对各自结果。失败保持“未验收”，旧链接修复不得删除用户投递记录。

### Ego Lite 点击前检查

全页快照可列出屏幕外元素。点击前将真实元素 scrollIntoView({block:'center'})，等待布局稳定，确认边界在视口内且 elementFromPoint 命中目标，再 click。2026-09-11 实测腾讯卡片在 y=775、窗口高704时点击未导航；滚动至视口后，同一链接正常打开。不得把未命中点击当404、登录或接口失败。每次核验后关闭临时详情页，或复用一个详情标签。

## 完成声明

详情验收等待完整岗位标题及职责正文就绪，不把仅有标题的异步页面当作完成。国内候选使用中文区域的独立匿名环境；错误包含岗位名称、地址和实际阶段。若官网脚本把详情导航到 about:blank，平台仅对此空白情况尝试一次不执行脚本的当前官网 HTML 读取，仍核对域名、HTTP 状态、岗位标题、职责和关闭/登录信号。静态正文不足则失败，不使用缓存或 Agent 自述补全。登录、验证码、真实关闭和其他跳转不走此回退。

### 固定 DOM 浏览器路线（browserListing）

HTTP 封装无法固定解析但公开页面可读时，可以改用平台浏览器 reader，不解码风控封装。读取 `adapter-browser-listing.mjs` 契约：manifest 增加 `browserListing: {listUrl, identityText, linkSelector, titleSelector, locationSelector}`。选择器必须来自实际 DOM，title/location 相对真实可见的岗位 anchor；listUrl 必须与批准入口完全一致。index 的 provider 使用 `'fetch': async (entry, ctx) => ctx.browserJobs(entry)`，不自行启动浏览器或返回缓存/fixture。

平台使用独立匿名 Chromium，不借用用户 Cookie，不点击、不翻页、不填写表单，单页最多100条，45秒超时后清理。包括脚本/CDN在内的请求和跳转都受精确 allowedHosts 与公网检查；必要资源域名须沿真实页面请求提交审核，不能自动放行。浏览器资源加载失败、登录/验证码、选择器变化和零条均报“未确认”，不假装成功空列表。浏览器依赖未安装时报告环境错误，不调用模型补救。

平台独立读取列表并逐字段比对插件结果，再核对三个真实详情；不叠加 HTTP、bootstrap 或 inlineDetails。运行不消耗模型 Token，但启动浏览器需要额外内存和时间。仅表示本页读取，不声称全量覆盖。测试用 fixture 必须与生产隔离。

浏览器结果比对以完整真实 URL 对应 title、location、company，不要求 JSON 属性顺序一致。候选可附加从官网 URL 路径（SPA 使用 #/ 路由）最后一段原样提取的字符串 id，平台单独核对编号并检查重复；不能改写源字段、删减/新增岗位或补造未观察到的描述等内容。其他编号格式须扩展验证契约，不能自行跳过检查。

续接前平台比较上次失败后的候选指纹，仅提示可能重复消耗，不禁用用户主动重试。补充说明可留空，平台把上次验收失败原因传给 Agent 诊断。路线批准记录仍有效，不重复授权。代码已完成时可“仅重新验收”，不调用模型；仍有 BLOCKED.md 不安装。新方案是线索而非新增权限，不能覆盖域名审核或真实验收。

### 公开响应取证与展开详情

预加载取证注册前先调用 `page.cdp('Page.enable')`；新建的 CDP 会话未启用 Page 时，注册可能返回成功但不在新文档执行。跨页面测试须验证“初始请求确实捕获”，不能仅凭注册 identifier 判断成功。

- Ego Lite 的 CDP requestId/响应缓冲可能无法跨调用使用，甚至同次 `Network.getResponseBody` 也可能失败。不要反复取同一失效编号。开发辅助模块 `adapter-network-capture.mjs` 导出 `publicCaptureScript(endpoint)`：只传已经观察且批准的一个公开列表端点，在正常 SPA 列表导航之前用 `page.evaluate(script)` 安装。它在页面内存观察一次 XHR/fetch，不重放、不读取请求头/Cookie；请求体上限16KB、响应2MB。返回页面后可按需读取 `window.__careerPublicCapture.record`，等待 response 非空；只输出公开查询参数、字段名和最多三个脱敏样本，不输出完整响应或个人信息。完成调用 `window.__careerPublicCapture.stop()` 清除。此辅助仅供开发，不导入生产插件。
- 页面刷新会移除普通内存观察器。若请求发生在初始加载，改用同模块 `publicCapturePreload(endpoint, documentUrl)`，不要反复尝试页面内安装。两个地址都必须实际观察并在批准范围内；在选定的 Ego Lite 标签执行 `page.cdp('Page.addScriptToEvaluateOnNewDocument', {source: publicCapturePreload(endpoint, documentUrl)})`，保存返回的 identifier，再正常导航一次到已批准 documentUrl。它仅在该精确地址的顶层文档、页面业务脚本执行前安装，响应仍只留页面内存。读出最小 schema 后，在 finally 中 `page.cdp('Page.removeScriptToEvaluateOnNewDocument', {identifier})` 并 `page.evaluate('window.__careerPublicCapture?.stop()')`，失败也清理。新标签有独立注册范围，必须先选对标签。参数必须来自正常页面请求，不重放、不读取登录凭证、不绕过验证。切换到预加载取证属于新方法，不被旧方法的历史失败次数永久封锁。
- 无 anchor 的卡片不代表没有详情路线。先正常点击最多三个真实岗位卡片，检查 page.info()/task.tabs()，记录实际 URL 与 data-id 对应关系；同时查看该页公开响应和页面内负责该卡片导航的局部代码。普通公开的导航映射不是风控签名；若明确看到固定详情路径和参数名，且三次真实点击吻合，可以据此实现固定映射并记录证据，不能仅凭 ID 猜链接。优先使用实际响应 URL 字段；若响应本身已是含岗位的 HTML，则可直接固定解析 HTML，无须强求 JSON schema。
- 官网只有原页展开时，可以使用 `manifest.inlineDetails`，字段为实际观察的 `listUrl`、`itemSelector`、`idAttribute`、`titleSelector`、`toggleSelector`、`bodySelector`。选择器仅接受简单标签/class和可选`:first-child`；编号属性必须是公开`data-*`。展开控件只允许非表单内的`tr`或`summary`，禁止投递按钮、任意脚本或无编号猜匹配。
- Job保留真实字符串`id`、纯文本`description`，并将`url`设为官网列表地址加浏览器文本定位和平台编号元数据：`listUrl + (new URL(listUrl).hash ? '' : '#') + ':~:text=' + encodeURIComponent(title).replace(/-/g, '%2D') + '&careerops-id=' + encodeURIComponent(id)`。`careerops-id`是本平台在fragment directive中的去重元数据，不是官网API/路由参数，不发送给HTTP服务器。这不是官网独立详情路由，页面必须明确提示“打开官网后点击同名岗位展开”；不得声称自动展开或深链接一定生效。同名岗位可保留，但必须用不同的真实ID区分；无真实列表URL或重复编号时停止，不制造ID。参考`adapter-inline-details.mjs`契约。`titleSelector`相对展开控件，`bodySelector`相对编号容器。
- 平台单独载入一次官网列表，按DOM公开编号定位三个不同岗位，核对名称，点击只读展开控件，并逐项比较可见正文与API描述。编号、正文不符、意外导航、登录、验证码、过期都不安装。独立详情链接的原验收不变；日常扫描仍使用HTTP固定解析，不调用浏览器或模型。只通过展开式验收不能声称所有岗位当前可投递。

分别报告“离线测试”“真实详情抽查”“启用及页面验收”。不能用满分/成功图标掩盖未做的阶段；抽样通过不代表全部岗位有效。没有真实证据就不能宣布真实接入成功。

## 阻塞处理：先验证路线，不反复重跑 Agent

### 按证据切换能力

首选方案是建议，不是唯一允许的方法。先利用已有响应、DOM、点击地址和代码确定缺口，再选最小可验证的方法；不要求每次把所有工具轮流跑一遍。

- 公开列表返回 JSON：固定解析真实字段；返回含岗位 HTML：解析实际 HTML，不强求 API。
- 请求发生在 SPA 切换：页面内监听；发生在初始加载/整页导航：预加载监听，不继续重复会被刷新销毁的捕获器。
- 同一请求的追踪值变化：在已观察到两次请求、确认纯追踪用途后，为 `publicCaptureScript(endpoint, {ignoreQueryParams: ['_ihr_log_trackId']})` 显式声明要忽略的键；预加载函数也接受该选项作为第三参数。键必须在原地址中存在且只能出现一次，最多4个，不是全局参数忽略。只在匹配时忽略，保留实际请求 URL；不改写/重放请求。域名、路径、其他参数仍严格匹配，不得忽略身份、分页、筛选或鉴权字段；不确定参数用途则不能忽略。
- 无岗位 anchor：读取卡片 data 属性、真实点击后的导航或新标签地址、局部公开路由代码。若真实响应及三次点击支持固定映射，可写固定解析；不能仅凭 ID 猜路由。公开页面内嵌 JSON、实际引用的静态数据也是候选路线，不下载遍历整个 bundle。
- HTTP 不可读但 DOM 可读：检查平台 browserListing/inlineDetails 是否适用。开发阶段可组合现有 Ego Lite DOM/CDP 能力或在候选内写必要辅助代码；生产必须使用平台支持且可独立验证的接口，不能偷接未受约束的浏览器执行器。

同一方法失败后应诊断并转向有依据的方法；禁止“尝试一次失败，因此所有方法都不许再试”的解释。围绕同一页允许为不同取证方法必要地重新导航，不翻页，不增加企业或详情样本。新方法要留下简短记录：方法、证据、结果、下一步；连续尝试没有新增证据时先重新评估缺口，不盲目重跑；仍有明确、不同且范围内的可验证方案时可继续，不按固定失败次数终止。已有明确新证据或新能力可续接；无需把预算耗尽才允许停止。

写 BLOCKED.md 前，在已有 ACCEPTANCE.md 中记录适用的替代方法为什么仍不可行或缺少什么，不强制试不适用的工具。需要登录/验证码、域名批准或真实平台能力变更时，如实请求处理；不是伪装崩溃，也不删除阻塞强行安装。不得自动循环启动 AI，未知方法不等于获得新权限。

### 一次授权公开适配（优先于下方逐次审核流程）

页面勾选一次授权并开始/重试后，服务端将授权保存在此候选的本地生命周期记录中；重试沿用，不以操作系统完全访问或候选自写字段代替授权。任务提示会明确是否启用此模式。

已获此授权时，从配置招聘域名或原批准官方来源出发，核实企业身份，沿实际公开链接、跳转、API 和必要资源连续开发。入口、路径、资源域名变化只需更新 ROUTE_REVIEW.json 和最小证据，不因此停止、反复审批或保留已解决的权限 BLOCKED.md。仍限一家公司、一页列表、三个详情，最多六个精确公开 HTTPS 域名与八条连通证据；不允许内网、凭证、其他企业、投递或自己安装。品牌冲突、来源不明、登录/验证码仍停止并报告具体原因。

平台验证路线格式及授权来源，再独立验证代码、真实列表和详情，成功自动安装绑定。域名授权不是代码通过验收；失败报红、保留旧版，用户可直接重试。不会自动循环调用 AI。未勾选/未保存此授权的历史候选仍采用下方逐次审核模式。

### 招聘入口发现与域名审核（未开启一次授权时）

**优先使用已配置且可打开的招聘首页。** 页面企业身份与目标一致时，`officialUrl`可以是配置中的招聘首页，不必是产品官网。以实际“招聘首页 → 跳转/岗位链接 → ATS/API”组成证据链即可提交审核；不因为缺少“产品主页反向链接”重新搜索或报开发阻塞。配置本身不是身份验证，品牌冲突、非目标租户或可疑跳转仍须停止。入口无法打开或身份不明时，才使用下面的官网发现预算。Moka等共享域名也不自动继承其他企业的权限。

平台将路线审核显示为独立的“等待路线审核 · 未安装”，不是红色失败。任务页“前往本企业审核并继续”直接定位企业面板；核对并批准后续接原候选，不要点“重新适配”浪费已有产物。清除已完成任务保留待审核事项。服务端没有发出完成确认时，不得因流结束而显示安装成功。

入口无法连接，不等于企业没有岗位，也不等于权限不足。先区分连接失败、登录/验证码、明确的岗位关闭/404；`ERR_CONNECTION_CLOSED` 是连接问题，不能标岗位过期。

1. **只读发现（不是生产授权）：** 先读此候选已有记录。入口失效且没有已批准路线时，可用 Ego Lite 最多一次“企业名 + 官网 招聘”搜索定位企业官网，再读取最多三个官网/导航页面。搜索只提供导航线索，不作为岗位或官方关系的证明。核实公司身份，沿页面实际 href 或重定向找“加入我们/招聘”，观察其公开 API 请求；不得猜主域名、ATS 租户、接口或详情路径，不分析其他企业、不扩大为批量扫描。无法确认官方身份就请用户提供官网。
2. **申请新路线：** 入口变化（即使同域），或真实跳转/API 涉及新域名时，只在候选目录写 `ROUTE_REVIEW.json`，随后停止开发等页面审核。只读发现允许观察官方指向的招聘服务和公开请求；不等于允许生产抓取、携带凭证或安装。最多六个精确域名、八条证据，均为公开 HTTPS，无 IP、内网、非标准端口或凭证。
3. **页面审核：** 企业 → 适配器设置，展示原入口、新入口、精确域名和完整来源链。用户打开来源核对企业身份及官方招聘跳转，勾选并点“批准路线”。Agent 的陈述只是线索，不能自行批准。批准只写本候选的权限记录，不调用 AI、不安装、不修改企业入口。
4. **续接原候选：** 点“继续 Agent 适配（原候选，消耗 Token）”，只补缺失代码/证据。平台在提示中提供批准的入口及域名；保持申请 JSON 原样，变化须重新审核。不重复整个开发过程，阻塞实际解决后才归档 `BLOCKED.md`。代码已完整时可直接“仅重新验收（零 Token）”；仍有阻塞则不安装。
5. **最后验收：** 批准域名不是批准代码。静态检查、离线 fixture、真实列表与三个详情、完整性及旧配置冲突检查仍必须通过，才一并更新本企业入口及绑定。失败保留旧配置。HTTP 重定向逐跳受域名限制，详情不得跳到未审核域名；登录和验证码仍交给用户。仅批准的公开 API 可进行一次匿名初始化，之后最多一页列表。

申请格式（仅格式示例，禁止当真实证据）：

```json
{
  "officialUrl": "https://www.example.com/",
  "entryUrl": "https://jobs.example.com/campus",
  "allowedHosts": ["jobs.example.com", "api.example.com"],
  "evidence": [
    {"fromUrl":"https://www.example.com/","toUrl":"https://jobs.example.com/campus","kind":"link","note":"官网加入我们链接；记录实际观察时间及企业身份依据"},
    {"fromUrl":"https://jobs.example.com/campus","toUrl":"https://api.example.com/positions","kind":"api","note":"招聘列表正常加载产生的公开请求；记录实际观察时间"}
  ]
}
```

`kind` 只能为 `link`、`redirect`、`api`。证据按顺序从 `officialUrl` 连接，后续 `fromUrl` 必须是先前已出现的地址，入口和所有申请域名都须在链上。申请存于候选，批准记录存于平台本地状态；候选不能以自写的 approved 字段授权。文件变更或丢失后原批准失效，不自动扩大域名。当前完全访问模式不是对恶意本地代码的强沙箱，仍需用户审核可信来源。

### 平台 Codex 权限与 Ego Lite

本节同时适用于 **WorkBuddy** 运行时（其内置的 CodeBuddy Code CLI）。两者的差异集中在权限闸门、工具白名单与配置目录隔离三处，验收标准完全一致。

- 设置页提供“Codex 完全访问（仅本平台）”。用户明确确认后开启，保存在本机 `web/.codex-permissions.local.json`（不提交 Git），刷新或重启后保留；关闭即恢复新任务的原有 Codex 配置。
- **WorkBuddy 有独立的“WorkBuddy 完全访问（仅本平台）”开关，与 Codex 的互不继承。** 只开 Codex 不会让 WorkBuddy 获得授权；反亦同。旧版只有 `fullAccess` 字段的配置文件对 WorkBuddy 一律视为未授权。
- **WorkBuddy 的配置目录必须隔离。** 其 CLI 默认使用桌面端 App 的 `~/.workbuddy`，两边会争抢同一份凭证刷新权，实测表现为“第一次调用 401、第二次正常”，并可能把桌面端踢下线。平台把 `CODEBUDDY_CONFIG_DIR` / `WORKBUDDY_CONFIG_DIR` 指向项目内隔离目录，并固定携带 `--no-session-persistence`。验收时须核对运行未在 `~/.workbuddy` 产生新日志或会话。
- **WorkBuddy 的可用工具按白名单裁剪**（`Read,Write,Edit,Bash,Glob,Grep,WebFetch,WebSearch`）。`Bash` 必须保留，Ego Lite 是通过它调用的。注意 init 事件里的 `tools` 数组是**注册表**，不反映白名单——判断裁剪是否生效要看行为（被禁的工具无法调用），不能看该列表。
- 无头模式下必须先有权限模式，任何工具才可用；该参数只在适配运行时按用户开关注入，不写入通用 argv。
- 所有平台 Codex 启动入口统一应用该设置，不修改全局配置，不改变已运行任务。完全访问允许写入系统账户可访问的项目外文件，不是候选目录沙箱；任务授权仍只允许修改指定候选，不得投递或修改绑定。macOS 权限与组织策略仍可能阻止操作。
- 当前 Codex + Ego Lite 自动适配先检查完全访问设置、CLI 参数支持、候选和临时目录写权限、真实 Ego Lite 连接。预检失败不调用模型。预检通过不代表真实岗位或适配器已验收。
- WorkBuddy 冷启动可能以 401 失败一次（凭证刷新），适配器对其做**有界重试**且只重试 401；其他错误立即上报，不重试成超时。
- 使用 Ego Lite 独立任务空间，不使用 Web DevHandler，不操作用户常驻项目页。用户接管后停止。遇阻塞写 BLOCKED.md；缺少 ACCEPTANCE.md 不视为成功，也不自动重跑旧任务。
- 菜单链接必须读取原始 href 和解析后的绝对 href，不按语义快照猜相对选择器。点击后检查 page.info() 与 task.tabs()；已观察到的官网 href 可直接打开。异步页面等待正文出现；初始空壳不是404。按钮通过 window.open 导航时，检查实际新增标签或正常点击产生的导航参数，不拼猜详情路由。旧 ACCEPTANCE.md 中实际观察过的完整官方详情 URL 可以作为导航入口：必须重新打开并核对当前标题、编号及职责，不能只引用历史结论；也不必强制重复一次容易被拦截的弹窗点击。这条已知 URL 路线应优先于消耗一次失败恢复机会。
- 提交前必须运行 `node plugin-audit.mjs plugins.local/<id>`、离线测试和语法检查。当前保守检查器要求沿用模板的 `'fetch': async (...) => {...}` 属性形式；测试使用 `import { strict as assert } from 'node:assert'`。不要通过削弱检查器消除报错。
- 未解决的 BLOCKED.md 优先于 ACCEPTANCE.md 阻止安装。解决后归档历史，不保留活动阻塞文件。代码已修好而验收失败时，在企业适配器设置点“仅重新验收（零 Token）”，不重新调用模型。
- 部分公开API需要匿名初始化（如B站CSRF）。只可声明同域或本候选已审核域名的 HTTPS `publicBootstrapUrl`，至多一次GET初始化加一页列表，初始化响应不能充当岗位证据。值仅存本次内存，不读取或保存用户登录凭证；真实登录/验证码仍停止。
- 官网列表来自静态数据资源时，允许一次已审核入口 HTML 加一次该 HTML 实际引用的 `.js`/`.json` 资源 GET，计为一页列表；不能同时叠加额外初始化、猜路径、遍历资源或执行下载脚本。资源须在已审核域名内，用资源真实响应核对岗位。此限制由验收器检查，不把所有两次请求都放行。
- 权限机制参考 [OpenAI 官方说明](https://learn.chatgpt.com/docs/security)。

1. **AI 服务拒绝 ≠ 官网不可读取。** 保存终端错误，检查已有文件和验收记录，不自动重试、不换模型规避政策。不让 Agent 再做整套开发；可独立验证用户授权的公开页面读取。若仍需 AI，应先明确合规范围、核对服务政策，再由用户决定。
2. **直连 API 的 401 ≠ 浏览器必须登录。** 先通过官网导航打开职位列表，等待实际职位元素出现。页面有“登录”按钮不等于读取被拦截；页面壳加载完成也不等于列表加载完成。只检查官网正常产生的请求，不猜接口、枚举路径或逆向风控签名。
3. **页面能读、HTTP 不能读：** 记录为“浏览器读取路线可行，HTTP 路线未验证”。可设计固定浏览器脚本读取 DOM 中的真实名称、链接、地点及描述；不得让模型每次解释页面，也不得宣称当前 HTTP 插件已支持浏览器。浏览器运行环境、用户会话和插件接入须单独实现与验收。
4. **页面确实要求登录/验证码：** 停止并交给用户；用户完成并确认继续后再验收。凭证不写入插件、日志或仓库。不伪造签名、不绕过限制。
5. **节省预算：** 先读已有 ACCEPTANCE.md 和错误末行，仅一页列表、最多三个详情；相同输入、方法和条件且没有新证据时不重复；有明确修正或新的可验证方案时可以继续。HTTP 改为已支持的固定 DOM 读取是新方案，不是重复 HTTP 取证，不受历史失败次数永久封锁。没有新方案或新证据则记录阻塞，不反复下载 bundle、不批量试探端点、不启动全量扫描。
6. **恢复时续接，不重建：** 保留原始失败记录，新增核验时间、证据和纠正结论。只补未完成环节；插件保持停用，直到两阶段验收通过。
