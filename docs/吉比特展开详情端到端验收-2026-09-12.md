# 吉比特展开详情：修复与端到端验收

日期：2026-09-12。仅吉比特；没有投递、AI岗位评估或全量招聘源扫描。

## 根因与修复

1. Ego Lite CDP 的响应读取报 `No resource with given identifier found`，同次调用也复现。新增开发期 `adapter-network-capture.mjs`，在页面内存暂存一个已观察、已批准端点的正常请求/响应；不重放，不读取请求头或Cookie，不保存完整响应文件。
2. 官网使用列表内展开，没有独立详情链接，但确有 `tbody.js-duty[data-post-id]`。新增按公开ID定位、只读展开、标题和正文比较的独立验收。生产插件仍是普通HTTP固定解析，浏览器辅助只用于开发与验收。
3. 两个“财务专员”有不同真实ID。采用官网列表URL的文本定位加平台ID元数据区分；它不是独立官网详情路径，不保证自动展开。界面明确提示打开后点击同名岗位展开。
4. 浏览器测试又发现扫描器按“企业＋岗位名”二次合并。已为带匹配真实ID的展开岗位保留独立去重键，原有URL历史去重继续有效，普通岗位逻辑不变。

规则写入 `docs/招聘源适配验收SOP.md`，平台 Agent 提示直接要求读取取证辅助和展开验收契约。候选代码由平台启动的 Agent 编写；测试人员未手工修改候选代码或信任配置。
